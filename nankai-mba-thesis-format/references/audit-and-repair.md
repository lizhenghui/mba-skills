# Word 检查、修复、复检

## 环境与初检

先定位并读取已安装的 `documents`/`docx` Skill，调用工作区依赖加载工具。使用返回的Python/Node及该Skill的渲染脚本；如其要求开始编辑标记，按其流程执行。不要将通用文档主题、全边框表格、Title样式或内容重写覆盖学校指定格式。

以临时目录保存中间产物，先记录原文件SHA-256并保留原件。以下变量须由当前环境确定：PYTHON=依赖Python，SKILL_ROOT=本Skill根，DOCS_ROOT=实际Word Skill根；所有路径加引号。

```bash
"$PYTHON" "$SKILL_ROOT/scripts/audit_docx.py" "input.docx" --json "before.json" --markdown "论文_格式问题清单.md"
```

脚本仅作候选预检，默认不启用无附件依据的MBA阈值。`--heading-mode two`只在已确认模式二时使用，`--citation-system author-year`只在已确认著者年制时使用；默认auto保留不确定性。`--reference-min`、`--english-reference-min`只传入有明确来源的学科要求，并在报告中记录。英文量按脚本估算，须逐条确认语种。

完整读取主文、表格、页眉页脚、文本框、浮动图、脚注、域、样式、分节、修订和批注。建立语义结构表：正文起止、摘要、目录、章节、题注、参考文献、附录等。样式名只是线索，目录缓存/列表不可当正文标题，封面表格不可当数据表。格式判定需解析段落和run直接属性、字符/段落样式继承、docDefaults及主题字体；无法求出实际值时待验证。旧脚本关于Normal/Heading的检查仅为样式候选，不足以证明实际正文格式。

按 common-issues.md 对14类逐项取证，渲染页码未产生前以段落号和文本片段定位。遇脚本不支持的复杂结构补人工检查，不能降低覆盖范围。

## 修复实现

1. 先确认结构和适用制式，再设置各节页面和不同组成部分的样式。保留原文件，另存新名。
2. 命名样式承载统一格式，处理直接格式覆盖时仅改有关属性，避免 `paragraph.text = ...` 或 `cell.text = ...` 重建段落导致超链接、书签、域、公式、修订、批注丢失。复杂DOCX优先定点OOXML修补；不得接受全部修订或删除批注，除非用户要求清稿。
3. 可使用本Skill的辅助脚本设置页面及经过人工确认的段落角色：

```bash
"$PYTHON" "$SKILL_ROOT/scripts/repair_docx.py" "input.docx" --plan "repair-plan.json" --out "论文_格式修订版.docx" --log "repairs.json"
```

计划格式：

```json
{
  "source_sha256": "原文件SHA-256",
  "page_geometry": true,
  "paragraphs": [
    {"index": 42, "text": "这一段的完整可见文字", "role": "body"},
    {"index": 43, "text": "第一章　绪论", "role": "chapter", "mode": "two"}
  ]
}
```

`index`为 `word/document.xml` 中 `w:body` 的直接子段落（只计w:p）的1起始编号；`text`为其中所有w:t拼接，用来防止错位；不要使用渲染页号或整篇XML的嵌套段落序号。只列明确需改且角色已核对的段落，不做全文猜测。角色支持正文、附录正文、摘要正文/标题、三级标题、图表题注、参考文献、致谢、目录标题，准确名字以脚本`--help`为准。脚本校验输入哈希与原文字，并保留ZIP其他部件和正文所有文本；不会填补未知来源、改文献内容、移动对象、更新域或重建分节。

脚本为所选段落创建NKF命名样式，移除相应段落格式覆盖，设置run字体字号以消除旧覆盖，保留正文强调/上下标；公式或包含受保护结构的段落会拒绝处理，转交Word Skill有针对性地修复。页面设置适用于全部节，存在经确认的特殊页设置时不要使用全节选项，改为定点编辑。

4. 图表以“正文说明→对象+题注+来源”整体核对。题注用Caption/SEQ/REF域时须保持书签和交叉引用；跨页表不仅重复表头，还需续表序及（续）。仅确认真实数据表后改三线边框，兼顾单元格/表样式边框和合并表头。不虚构图像来源或重画带数据的图。
5. 参考文献与引文按reference-style.md核对。排序/编号需同步全文引用，不能用简单正则全局替换。
6. 用真实分页/分节符控制页码和章起页，检查页眉页脚继承、首页及奇偶设置；正文页眉取章标题。不要所有章强制右页；不得用空行堆版。
7. 使用真实TOC、PAGE、SEQ、REF、PAGEREF等域，实际更新显示结果。Word更新字段/导出PDF是首选；其他引擎须验证域和中文字体支持。不要把设置 `w:updateFields` 当作已经更新，也不要假定Pages完整兼容所有Word域。只有实际分页可支撑静态目录兜底，并记录限制。

## 复检与交付门槛

- 重新运行初检工具、ZIP完整性检查和14类清单。与before对比，沿用问题编号；新出现的问题也需处理。
- 比较正文/表格文本、公式节点、图片内容哈希、超链接/书签/脚注/批注/修订等；预期变化（如题注编号/域显示）记录在日志，非预期变化必须解决。原文件哈希保持不变。
- 先核实渲染环境有宋体、黑体、仿宋及英文所需字体（或可核实的等效字体）；字体替代会影响分页。用Word Skill的 `render_docx.py --help` 确认当前接口，再渲染并打开每一页图像检查缺字、错位、截断、页眉页码、孤立标题、图表/续表、目录页码、空白页。不要仅抽查或只看PDF文本。打印和装订要求单列人工确认。
- 渲染失败时依据日志检查中文字体/引擎，可用可访问的Word导出替代并重新看图。无法完成时保留“已修改待验证”，如实交付修订稿和未验证范围，不冒称可提交终稿，也不无限重试。
- 交付问题清单及（修复模式）新DOCX。内部备份、JSON、PDF和PNG不默认交付。缺少论文输入时只说明需要待检查DOCX，不能把规范附件当论文。
